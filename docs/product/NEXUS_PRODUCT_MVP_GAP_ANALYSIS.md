## P1 — Partial: artifacts exist; executable intent-to-plan workflow unproven

**Exists (observed):** `agents/embedded-systems/src/nexus_embedded_systems/workflows/project_initialization/providers/llm_provider.py` implements staged interpretation, brief, requirements and architecture with validation/repair; `providers/fixture_provider.py` and `fixture_router.py` return materialized golden families by default. `workflows/component_planning/compose.py`, `derive_roles.py`, `derive_constraints.py` and `propose_candidates.py` assemble component planning. `workflows/layered_architecture/compose_electrical.py` composes electrical interfaces. `apps/api/src/nexus_api/main.py` persists initialization and exposes artifacts/workspaces. `packages/board/src/nexus_board/firmware/scaffold.py` and `services/workspace_runtime.py` provide executable workspace operations.

**Partial/missing:** `project_initialization/next_action_selector.py` selects one next action; that is not demonstrated as a complete approved dependency-ordered executable plan. `workflows/project_modification/service.py::ModificationService.submit_turn` explicitly rejects non-fixture modification modes. A live initialization path and a fixture-only conversation are not a coherent live project lifecycle. No linked live goal-to-approved-plan-to-build demonstration was found in the inspected coverage.

**Coverage:** `apps/api/tests/test_initialize_endpoint.py`, `packages/contracts/tests/test_component_plan_semantics.py`, and `evals/embedded_project_initialization/cases/{golden,adversarial}.yaml` support initialization and validation. `scripts/run-evals.sh` selects a scripted fake gateway; those evals do not demonstrate live intent interpretation. `apps/web/e2e/phase12-component-plan.spec.ts` covers component UI interactions in fixture mode.

**Smallest change / missing integration:** extend the owning embedded workflow with a reviewable plan tied to existing artifacts, dependencies and tool operations; reconcile non-fixture project updates. Add goal → approved plan → matching workspaces → actual build HTTP/UI coverage, including rejected decisions and restart. Reuse shared versioned contracts if new cross-module fields are needed; require compatibility tests. Risks: invented component compatibility, plan/source divergence, fixture routing mistaken for general interpretation, and ambiguity applied without approval.

## P2 — Partial primitives; closed-loop agent repair missing as a demonstrated workflow

**Exists (observed):** `apps/api/src/nexus_api/main.py::_build_firmware_patch_generator` and `_build_analysis_patch_generator` wire live generators for configured llm/shadow modes with a credential. `packages/board/src/nexus_board/firmware/{patch,live_patch_generator,toolchain}.py` provides context, guarded operations and compile mapping; `analysis/live_patch_generator.py` provides analysis proposals. `packages/board/src/nexus_board/execution/job_service.py` manages execution; `packages/board/src/nexus_board/services/verification_service.py` promotes deterministic evidence. `packages/circuit-simulation/README.md` describes live Wokwi prerequisites and surrogate limits.

**Fixture/manual/dev-only boundary:** `apps/api/tests/test_golden_lifecycle_http_api.py::test_golden_lifecycle_over_http_only` sets firmware stub on, analysis stub off, and uploads checked-in firmware, analysis and CSV. It validates a real HTTP/service chain with real Python computation, not agent-written firmware or sensor/simulator-derived observations. `packages/board/tests/test_phase16i_golden_e2e.py::_run_golden_g1` injects synthetic noisy data or a crashing analysis script; no agent diagnoses and repairs it. Its live PlatformIO test is separate from G1. `test_firmware_live_patch_generator.py` and `test_analysis_live_patch_generator.py` use `FakeModelGateway` despite their names. G3/G4 are opt-in live-model variants, not evidence of the full product correction loop.

**Missing integration / smallest change:** connect existing patch, compile, simulator, output import and deterministic promotion operations in a bounded embedded workflow: inspect actual diagnostics, request a reviewed correction, rerun affected steps, stop visibly on exhaustion/cancel. Ensure the simulator consumes the newly produced firmware, not an unrelated preconfigured ELF, and analysis consumes its observations. Add a deterministic scripted-model regression plus a separately recorded live-model acceptance run. Real build failure, failed observation, rejected patch, cancellation and exhausted retries need linked tests. Risks: stub fallback (`firmware/toolchain.py::_use_platformio_stub` defaults based on `pio` availability), analysis stub defaults, simulator token/toolchain availability, unsafe generated edits, and passing an unrelated synthetic dataset.

## P3 — Substantial core architecture; cross-tool continuity partial

**Exists (observed):** `packages/board/src/nexus_board/services/invalidation_service.py::{record_run,stamp,basis_is_current}` links runs, producer snapshots, requirements and criteria, evaluates captured dependency hashes, and preserves historical observations. `services/verification_service.py` exposes evidence chains and gated promotions. `packages/persistence/src/nexus_persistence/{factory.py,file_store/local.py}` and the SQLite backend built through the factory support durable metadata and blobs. `firmware/patch.py::assemble_firmware_generation_context` gathers versioned artifact references and bounded snapshot contents.

**Coverage:** `packages/board/tests/test_m5_invalidation.py` exercises relevant/unrelated/transitive changes, unknown basis, immutable history, SQLite restart, authorized current-run revalidation and idempotence. Some setup directly constructs legacy revisions; that is a deliberate unknown-basis regression, not a user action. G1 SQLite restart tests compare evidence and snapshot bytes. `apps/api/tests/test_golden_lifecycle_http_api.py` reads original analysis/input bytes from the run snapshot and asserts deterministic authority and idempotent promotion.

**Partial/missing:** these tests do not prove firmware → live simulation observations → analysis continuity or that an agent consumes the correct current failure context. Accepted-artifact invalidation must not be generalized to every unaccepted editor keystroke. #109 would add HTTP/UI surfacing but needs its own reviewed integration. Missing tests: accepted input change through the normal user workflow across all three tools, restart and source/output identity traversal, stale-run replay rejection there, and safe re-verification. Smallest change: carry existing run/output/snapshot/dependency references across tool handoffs and test them; do not create another state store. Risks: incomplete dependency capture, stale configured ELF, missing data provenance, and a historical PASS displayed as current validity.

## P4 — Partial UI, more implemented than its README states

**Exists (observed):** `apps/web/src/artifacts/renderers/registry.tsx` registers firmware, analysis, test plan and risk renderers; these are not all placeholders. `artifacts/firmware/workspace.tsx` exposes scaffold, patch review/apply, compile and history. `artifacts/analysis/workspace.tsx` exposes scaffold, input and patch/run interactions. `components/execution/{ExecutionLogViewer,ExecutionOutputs,CancelExecution}.tsx` provide execution primitives. `views/EvidenceExplorer.tsx` displays requirement/test, assessment/authority, criterion, result and evidence identifiers with Test Plan/Analysis navigation. Current source lacks #109's applicability reason rendering. An absent artifact can still produce an honest unavailable workspace.

**Coverage:** `apps/web/e2e/persistence.spec.ts` creates a fixture project, reloads, opens firmware/analysis, expects absent Test Plan/Risk Register until generated, submits a fixture turn, and inspects history. `artifacts/{firmware,analysis}/workspace.test.tsx`, `artifacts/analysis/productization.test.tsx` and `views/EvidenceExplorer.test.tsx` provide component coverage; mocked clients are not browser-to-tool proof. Desktop shipping/persistence boundary is described in `apps/desktop/README.md`.

**Missing integration / smallest change:** connect the plan/approval and correction workflow to these existing views; prove output inspection, cancellation, failure recovery, live-mode labels, current applicability/reasons and revision navigation across reload/restart. Add one full golden browser/desktop journey, keyboard checks, and honest tool-unavailable cases. Do not rebuild the UI or add an orchestration dashboard. Risks: stale local state after a run, disconnected approval controls, inaccessible primary controls, and hiding fixture mode behind a success badge. Accessibility and install usability were not established by this source audit.

## P5 — Missing evidence in inspected sources

No record of three external target-user sessions was supplied or found in the inspected product docs and test inventory. This is an evidence gap, not a claim that no user has ever tried Nexus. Repository tests cannot substitute for external validation. Smallest change: prepare a narrow task and observation protocol, recruit three external participants, record consented sanitized outcomes/assistance and evidence interpretation, then map blockers to P criteria. No new telemetry framework is necessary. Risks: founder/developer assistance masking failure, non-target participants, private participant data in Git, and treating positive feedback as workflow completion.
